# Agent Guide — STM32L152RE LoRaWAN Sensor Node

Agent-focused development reference for this firmware project. Covers code structure, build/flash/debug workflow, and conventions to follow when modifying or extending the codebase.

---

## Quick Reference

| Item | Value |
|------|-------|
| **MCU** | STM32L152RET6 (Cortex-M3, 512 KB Flash, 120 KB RAM) |
| **Radio** | SX1276 (AS923 868 MHz) |
| **Region** | AS923 (`ACTIVE_REGION = LORAMAC_REGION_AS923`) |
| **Class** | A (default), B optionally enabled via `CLASSB_ENABLED` CMake flag |
| **Build system** | CMake (cross-compile, out-of-tree) |
| **Toolchain** | `arm-none-eabi-gcc` (provided by STM32CubeIDE or standalone) |
| **Debug probe** | ST-LINK/V2 (on-board), OpenOCD or STM32CubeProgrammer |
| **Serial console** | UART2 at 115200 baud, `PA2 (TX)` / `PA3 (RX)` |
| **Firmware version** | `src/app/common/firmwareVersion.h` — change `FIRMWARE_VERSION` string here |
| **GitHub version** | `src/app/common/githubVersion.h` — auto-generated by CMake from git SHA |

## Code Structure Deep Dive

### `main.c` — Application Entry Point

`src/app/sensor-node/main.c` is the sole application entry point. Flow:

1. `BoardInitMcu()` → clock tree, GPIO, NVIC, low-power domains
2. `BoardInitPeriph()` → UART, SPI, I2C, ADC, radio
3. Init three `TimerEvent_t` objects (Tx timer, LED1 blink, LED2 blink, beacon timer)
4. `LmHandlerInit(&LmHandlerCallbacks, &LmHandlerParams)` — register the stack
5. `LmHandlerPackageRegister(PACKAGE_ID_COMPLIANCE, ...)` — mandatory compliance package
6. `LmHandlerJoin()` — start OTAA join procedure
7. `while(1)` event loop:
   - `CliProcess()` — poll UART, handle `ESC+N` factory reset
   - `LmHandlerProcess()` — process pending LoRaMAC events
   - `UplinkProcess()` — schedule next TX if timer fired
   - `BoardLowPowerHandler()` — enter WFI sleep if idle

### Timer Events

| Timer | Frequency | Action |
|-------|-----------|--------|
| `TxTimer` | 5000 ms ± 1000 ms random | Sets `IsTxFramePending=1`, triggers `PrepareTxFrame()` |
| `Led1Timer` | 25 ms | Turns off LED1 (TX indicator) |
| `Led2Timer` | 25 ms | Turns off LED2 (RX indicator) |
| `LedBeaconTimer` | 5000 ms | Keeps LED2 on while beacon received (Class B) |

### Cayenne LPP Payload Structure

```
Port 2 (LORAWAN_APP_PORT):
  Channel 0  — LPP_DIGITAL_INPUT  (1 byte): LED state from downlink
  Channel 1  — LPP_ANALOG_INPUT   (2 bytes): battery level 0–254 → ×100
```

To add new sensors, call additional `CayenneLppAdd*()` functions in `PrepareTxFrame()`. Available types:

| Type ID | Function | Size | Unit |
|---------|----------|------|------|
| 0 | `CayenneLppAddDigitalInput(ch, val)` | 3 B | bool |
| 2 | `CayenneLppAddAnalogInput(ch, val)` | 4 B | ×0.01 signed |
| 103 | `CayenneLppAddTemperature(ch, celsius)` | 4 B | ×0.1 °C |
| 104 | `CayenneLppAddRelativeHumidity(ch, rh)` | 3 B | ×0.5 % |

### CLI / Serial Console

**Serial config:** UART2, 115200-8-N-1, pins `PA2 (TX)` / `PA3 (RX)`.

| Key | Action |
|-----|--------|
| `ESC + N` | Factory reset NVM (clears OTAA session), then hang. **Requires manual reset after.** |
| All other input | Ignored (only the escape sequence is recognized) |

`CliProcess()` is called every iteration of the main loop — it polls UART character-by-character.

### Soft-SE (Secure Element)

Keys are statically defined in `src/peripherals/soft-se/se-identity.h`:

| Key | Purpose | Fixed or Dynamic |
|-----|---------|-----------------|
| `APP_KEY` | Root application key (LoRaWAN 1.0: `GEN_APP_KEY`) | Fixed — used in OTAA join |
| `NWK_KEY` | Root network server key (LoRaWAN 1.0: `APP_KEY`) | Fixed — used in OTAA join |
| `J_S_INT_KEY`, `J_S_ENC_KEY` | Join session keys (1.1 only) | Zero-filled, set during join |
| `F_NWK_S_INT_KEY`, `S_NWK_S_INT_KEY`, `NWK_S_ENC_KEY` | Network session keys | Set after successful join |
| `APP_S_KEY` | Application session key | Set after successful join |
| Multicast keys | Group multicast support | Zero-filled (not used) |

**To change OTAA credentials**, edit `se-identity.h` — update `LORAWAN_DEVICE_EUI`, `LORAWAN_JOIN_EUI`, and either `APP_KEY` or `NWK_KEY` depending on which is correct for your stack version.

### NVM (Non-Volatile Memory)

NVM stores the join session state (`DevAddr`, `NwkSKey`, `AppSKey`, `FCntUp/Down`) so the device can rejoin without re-entering credentials. Persisted to the `EEPROM` sector of flash at `0x0807E000` (last 512 bytes of flash).

- `NvmDataMgmtStore()` — write context to flash
- `NvmDataMgmtRestore()` — read context on boot; if restored successfully, skip OTAA and use stored session
- `NvmDataMgmtFactoryReset()` — erase all stored NVM

## Build

### Prerequisites

- [arm-none-eabi-gcc toolchain](https://developer.arm.com/tools-and-software/open-source-software/developer-tools/gnu-toolchain/gnu-rm/downloads)
- CMake ≥ 3.6
- Git (for `githubVersion.h` generation)

### Build commands

```bash
# Windows (PowerShell)
cmake -S . -B build -DTOOLCHAIN_PREFIX=C:/PROGRA~1/ARM~1.2-GNU1/arm-none-eabi/bin
cmake --build build --config Release

# Linux / WSL
cmake -S . -B build -DTOOLCHAIN_PREFIX=/usr/bin/arm-none-eabi-
cmake --build build --config Release
```

The default build type is Release. To build Debug:

```bash
cmake -S . -B build -DTOOLCHAIN_PREFIX=... -DCMAKE_BUILD_TYPE=Debug
cmake --build build --config Debug
```

### Output artifacts

| Artifact | Path | Description |
|----------|------|-------------|
| `.elf` | `build/src/app/lorawan-sensor-node.elf` | Full debug binary (symbols, DWARF) |
| `.bin` | `build/src/app/lorawan-sensor-node.bin` | Raw binary (flash with STM32CubeProgrammer) |
| `.hex` | `build/src/app/lorawan-sensor-node.hex` | Intel HEX (flash with OpenOCD) |
| `.map` | `build/lorawan-sensor-node.map` | Linker memory map (size analysis) |
| `githubVersion.h` | `build/src/app/common/githubVersion.h` | Auto-generated from `git rev-parse HEAD` |

### CMake options

| Option | Default | Description |
|--------|---------|-------------|
| `CLASSB_ENABLED` | ON | Enable Class B beacon/clock-sync support |
| `TOOLCHAIN_PREFIX` | *(required)* | Path prefix to `arm-none-eabi-*.exe` binaries |

## Flash & Debug

### Option 1 — STM32CubeProgrammer (CLI)

```bash
# Flash .bin (fastest, no verify)
STM32_Programmer_CLI -c port=swd -w build/src/app/lorawan-sensor-node.bin 0x08000000 -v -rst

# Flash .bin without reset
STM32_Programmer_CLI -c port=swd -w build/src/app/lorawan-sensor-node.bin 0x08000000 -v
```

### Option 2 — OpenOCD (CLI)

```bash
# Flash .hex + reset
openocd -f interface/stlink.cfg -f openocd.cfg \
        -c "program build/src/app/lorawan-sensor-node.hex verify reset exit"

# Flash .bin directly
openocd -f interface/stlink.cfg -f openocd.cfg \
        -c "init; reset halt; flash write_image erase build/src/app/lorawan-sensor-node.bin 0x08000000 bin; reset run; exit"
```

### Option 3 — VS Code + Cortex-Debug

Launch configuration is pre-defined in `.vscode/launch.json`. It uses OpenOCD as the debug server and GDB as the debugger.

1. Install the **Cortex-Debug** extension in VS Code.
2. Press `F5` or select **Debug-lorawan-sensor-node** from the Run & Debug panel.
3. The debugger will: connect to OpenOCD → load the `.elf` → flash → halt at `main()` entry.

**Prerequisites for VS Code debug:**
- `openocd.exe` and `arm-none-eabi-gdb.exe` must be found at the paths in `launch.json` (default: STM32CubeIDE installation).
- The target board must be connected via ST-LINK before starting the debug session.

### Option 4 — STM32CubeIDE (GUI)

1. Import the project as "Existing CMake Project".
2. Ensure the toolchain points to the same `arm-none-eabi-gcc` used from CLI.
3. Build (`Ctrl+B`), then Run/Debug (`F11`).

## Adding a New Region

To switch from AS923 to another region (e.g., EU868):

1. Include the region header in `main.c`:
   ```c
   #include "RegionEU868.h"
   ```
2. Change the compile-time define (in `CMakeLists.txt` or `main.c`):
   ```c
   #define ACTIVE_REGION LORAMAC_REGION_EU868
   ```
3. Rebuild. No other code changes are needed — `RegionCommon` dispatches to the correct region implementation automatically.

## Enabling Class B

Class B adds beacon reception and scheduled ping slots. To enable:

```bash
cmake -S . -B build -DTOOLCHAIN_PREFIX=... -DCLASSB_ENABLED=ON
cmake --build build --config Release
```

When enabled, the `LmhpClockSync` package is compiled and the device will attempt to synchronize to LoRaWAN beacons after joining. The `LedBeaconTimer` and `OnBeaconStatusChange` handler in `main.c` already handle beacon state visualization.

## Security & Keys

⚠️ **Never commit `se-identity.h` with production keys.** The current keys are placeholder values. Before deploying:

1. Generate a unique `DevEUI` and `JoinEUI` (from your LoRaWAN network server).
2. Generate an `AppKey` using your network server's key generator.
3. Update `LORAWAN_DEVICE_EUI`, `LORAWAN_JOIN_EUI`, and `APP_KEY` / `NWK_KEY` in `src/peripherals/soft-se/se-identity.h`.

For **LoRaWAN 1.0.x** devices:
- `APP_KEY` in code = `LORAWAN_GEN_APP_KEY` (the real root key)
- `NWK_KEY` in code = `LORAWAN_APP_KEY`

For **LoRaWAN 1.1.x** devices:
- `APP_KEY` in code = `LORAWAN_APP_KEY`
- `NWK_KEY` in code = `LORAWAN_NWK_KEY`

## Low-Power Operation

The main loop calls `BoardLowPowerHandler()` whenever `IsMacProcessPending == 0`. The MCU enters **Stop mode** (RTC running on LSE, ~1.2 µA sleep current) and wakes on:

- SX1276 DIO interrupt (TX done, RX data ready, beacon)
- RTC alarm (for Class B ping slot scheduling)
- UART character arrival (CLI polling)

To further reduce power:
1. Reduce `APP_TX_DUTYCYCLE` to a larger value (longer sleep between TX).
2. Disable `LORAWAN_DUTYCYCLE_ON` only for test purposes (not ETSI-compliant).
3. Use `BoardGetBatteryLevel()` to monitor supply voltage and trigger deep-sleep events.

## Conventions for Agents

When working in this repository:

- **Do not modify** `githubVersion.h` — it is auto-generated by CMake on each build.
- **Do not modify** `build/` contents directly — always rebuild via CMake.
- **Commit format:** `type: short description` (e.g., `feat: add humidity sensor`, `fix: correct AS923 channel frequencies`).
- **New files** go under `src/app/` (application), `src/board/` (BSP), `src/mac/` (MAC), or `src/peripherals/` — update the corresponding `CMakeLists.txt` in that directory.
- **New peripherals** (sensors, etc.): implement as a board driver in `src/board/` following the pattern of `adc-board.c` / `i2c-board.c`, then consume in `main.c` or a new `src/app/` module.
- **Region changes** should not touch `main.c` beyond the `ACTIVE_REGION` macro — region logic lives entirely in `src/mac/region/`.
- **Always verify** that `build/src/app/lorawan-sensor-node.elf` is generated before flashing — the `.bin`/`.hex` are derived from it.
- **Check section sizes** after each build — use the `arm-none-eabi-size` output printed by CMake to confirm the binary fits within 512 KB flash and 120 KB RAM.
